# Eval template rules (for review)

One row per template in `evals/build_eval_sets.py`: the pattern it fills in, one example sentence it produces, and the rule that assigns that example's label. Every item a template produces is correct by construction -- the label is derived from the same slots used to build the sentence -- so reviewing the rule here covers every sentence the template can produce, not just the one shown.

Replaces the earlier `docs/eval_label_sample.md` (a random sample of template output), which reviewed sentences one at a time rather than the logic that generates and labels all of them.

**No live API call has been made anywhere in building or rendering these.**

## Intent parsing templates (`parse_intent`)

| Template | Pattern | Example | Label | Rule |
|---|---|---|---|---|
| ASK_ANALYSIS: compare | `is {a} different between {b} groups? / does {a} differ by {b}? / compare {a} across {b} / how does {a} vary with {b}? / check whether {a} depends on {b}` | `is income different between gender groups?` | `{'needs_clarification': False, 'type': 'ask_analysis'}` | Any phrasing asking whether an outcome differs by/varies with/depends on a group column maps to ask_analysis; the specific comparison verb doesn't change the intent type. |
| ASK_ANALYSIS: association | `is there a relationship between {a} and {b}? / does {a} correlate with {b}? / how are {a} and {b} related?` | `is there a relationship between income and age?` | `{'needs_clarification': False, 'type': 'ask_analysis'}` | Phrasing asking about a relationship/correlation between two numeric columns maps to ask_analysis. |
| ASK_ANALYSIS: trend | `has {a} changed over {t}? / is there a trend in {a} across {t}?` | `has income changed over month?` | `{'needs_clarification': False, 'type': 'ask_analysis'}` | Phrasing asking about change over a time column maps to ask_analysis. |
| ASK_ANALYSIS: higher-in-one | `is {a} higher in one {b} than another?` | `is income higher in one clinic than another?` | `{'needs_clarification': False, 'type': 'ask_analysis'}` | A magnitude-comparison phrasing over a group column still maps to ask_analysis. |
| ACCEPT: plain | `yes / sounds good / run it / accept / go with that / that works / do it` | `yes` | `{'needs_clarification': False, 'type': 'accept', 'persona': None}` | A bare agreement word/phrase with no persona named maps to accept with persona=None (accepts whichever proposal is on screen). |
| ACCEPT: persona named | `go with {persona} / use {persona}'s proposal / ...` | `professor sounds right` | `{'needs_clarification': False, 'type': 'accept', 'persona': 'professor'}` | Naming a persona (professor/consultant/maverick) sets label.persona to that name. |
| MODIFY: alpha | `set alpha to {x} / use alpha = {x}` | `use alpha = 0.01` | `{'needs_clarification': False, 'type': 'modify', 'alpha': 0.01}` | A stated significance level maps to modify with label.alpha set to that float. |
| OVERRIDE: function named | `override to {fn} / use {fn} anyway` | `override to welch_t` | `{'needs_clarification': False, 'type': 'override', 'function': 'welch_t'}` | A registered function name present in the text sets label.function to it (matched against the registry, longest name first -- see `_named_function` in llm/fallback.py). |
| EXPLAIN: term | `what is {term}? / explain {term}` | `what is a p-value?` | `{'needs_clarification': False, 'type': 'explain', 'topic': 'a p-value'}` | A glossary-style term after 'what is'/'explain' sets label.topic to that term verbatim. |
| EXPLAIN: why not | `why not {fn}?` | `why not welch_t?` | `{'needs_clarification': False, 'type': 'explain', 'topic': 'welch_t'}` | 'why not X' sets label.topic to the named function, same as a term. |
| GOTO_STAGE | `go to the {stage} stage / jump to {stage}` | `go to the profile stage` | `{'needs_clarification': False, 'type': 'goto_stage', 'target_stage': 'profile'}` | A named stage sets label.target_stage to it. |
| UNDO | `undo / go back / revert that / undo the last step / take that back / go back one step` | `undo` | `{'needs_clarification': False, 'type': 'undo'}` | A fixed set of undo/revert phrasings, no slots. |
| BRANCH | `create a branch called {name} / branch {name}` | `create a branch called alt-cleaning` | `{'needs_clarification': False, 'type': 'branch', 'name': 'alt-cleaning'}` | A named branch sets label.name to it. |
| SWITCH_BRANCH | `switch to branch {name} / switch to the "{name}" branch` | `switch to branch alt-cleaning` | `{'needs_clarification': False, 'type': 'switch_branch', 'name': 'alt-cleaning'}` | A named branch sets label.name to it. |
| SKIP | `skip this / not now / move on / skip / let's move on / not right now / pass on this / skip ahead` | `skip this` | `{'needs_clarification': False, 'type': 'skip'}` | A fixed set of skip/decline phrasings, no slots. |
| EXPORT | `export this to a notebook / write it up / export the notebook / can you export this / write this up as code / generate the notebook / export / write up the analysis` | `export this to a notebook` | `{'needs_clarification': False, 'type': 'export'}` | A fixed set of export/write-up phrasings, no slots. |
| SETTINGS | `show me the ledger / what have I run so far / show history / what have I done / show me what tests ran / ledger / what's my test history / show the ledger` | `show me the ledger` | `{'needs_clarification': False, 'type': 'settings'}` | A fixed set of history/ledger phrasings, no slots. |
| SHOW: plot | `plot {a} against {b}` | `plot income against satisfaction` | `{'needs_clarification': False, 'type': 'show'}` | A plot/chart request over two columns maps to show. |
| SHOW: distribution | `show me the distribution of {a}` | `show me the distribution of income` | `{'needs_clarification': False, 'type': 'show'}` | A distribution request over one column maps to show. |
| ANSWER_CLARIFICATION: confirmation | `yes/yeah/correct/... , no/nope/...` | `yes` | `{'needs_clarification': False, 'type': 'answer_clarification', 'confirmed': True}` | A bare confirmation word is only read as answer_clarification when context.awaiting_answer is True (a question is actually pending); otherwise the same word is OTHER (see the realistic set's category F for the false-positive case). |
| ANSWER_CLARIFICATION: design word | `paired / independent / repeated / same people / ...` | `paired` | `{'needs_clarification': False, 'type': 'answer_clarification', 'design': 'paired'}` | A bare design-indicating word, only when context.awaiting_answer is True, sets label.design to the Design enum value it maps to (paired/independent/repeated). |
| OTHER | `hmm / I don't know / what about it / ok / ? / tell me more / interesting / hm not sure / maybe / I guess / sure whatever / huh / well / right / I see` | `hmm` | `{'needs_clarification': True, 'type': 'other'}` | Text matching no other rule falls below Section 9.1's confidence floor and maps to other, with needs_clarification=True -- the orchestrator asks rather than guessing. |

## QuestionSpec building templates (`build_question_spec`)

| Template | Pattern | Example | Label | Rule |
|---|---|---|---|---|
| COMPARE_GROUPS: independent (stated) | `is {a} different between {b} groups? these are unrelated, independent samples` | `is income different between gender groups? these are unrelated, independent samples` | `{'needs_clarification': False, 'goal': 'compare_groups', 'variables': {'outcome': 'income', 'group': 'gender'}, 'design': 'independent'}` | The text names the outcome and group columns and explicitly says the samples are independent, so design=independent -- read off the wording, never inferred from the data. |
| COMPARE_GROUPS: paired (stated) | `did {a} change after the intervention, same subjects measured before and after` | `did income change after the intervention, same subjects measured before and after` | `{'needs_clarification': False, 'goal': 'compare_groups', 'variables': {'outcome': 'income', 'group': 'period'}, 'design': 'paired'}` | 'same subjects ... before and after' explicitly states paired design. |
| COMPARE_GROUPS: repeated (stated) | `{a} was measured three times on the same subjects across {b}` | `income was measured three times on the same subjects across region` | `{'needs_clarification': False, 'goal': 'compare_groups', 'variables': {'outcome': 'income', 'group': 'region'}, 'design': 'repeated'}` | 'measured three times on the same subjects' explicitly states repeated design. |
| COMPARE_GROUPS: design unstated (needs clarification) | `is {a} different by {b}?` | `is income different by gender?` | `{'needs_clarification': True, 'goal': 'compare_groups', 'variables': {'outcome': 'income', 'group': 'gender'}, 'design': 'unknown', 'note': 'wording does not say independent vs. paired/repeated'}` | No cue distinguishes independent samples from paired/repeated measurement, so design stays 'unknown' (not a guess) and needs_clarification=True: the downstream validate_spec/ambiguity check must ask, per Section 7.1's rule that design is never inferred from wording alone. |
| ASSOCIATION | `is there a relationship between {a} and {b}?` | `is there a relationship between income and age?` | `{'needs_clarification': False, 'goal': 'association', 'variables': {'x': 'income', 'y': 'age'}, 'design': 'unknown'}` | design='unknown' here because the goal has no design concept at all, not because anything is ambiguous -- needs_clarification stays False. |
| DISTRIBUTION_FIT | `is the average {a} equal to {ref}?` | `is the average income equal to 50?` | `{'needs_clarification': False, 'goal': 'distribution_fit', 'variables': {'outcome': 'income'}, 'design': 'unknown', 'reference_value': 50}` | The stated number sets reference_value; design is not applicable to this goal. |
| EQUIVALENCE | `is {a} practically the same between {b} groups (independent, unrelated samples), within a small margin?` | `is income practically the same between gender groups (independent, unrelated samples), within a small margin?` | `{'needs_clarification': False, 'goal': 'equivalence', 'variables': {'outcome': 'income', 'group': 'gender'}, 'design': 'independent'}` | Equivalence testing between groups carries the same design ambiguity as compare_groups; the pattern states 'independent, unrelated samples' explicitly so design=independent is actually read off the text, not assumed the way an earlier draft of this generator did. |
| TREND | `has {a} changed over {t}?` | `has income changed over month?` | `{'needs_clarification': False, 'goal': 'trend', 'variables': {'outcome': 'income', 'time': 'month'}, 'design': 'unknown'}` | design is not applicable to this goal. |
| DESCRIBE | `summarize {a} / give me an overview of {a}` | `summarize income` | `{'needs_clarification': False, 'goal': 'describe', 'variables': {'outcome': 'income'}, 'design': 'unknown'}` | design is not applicable to this goal. |
| MISSINGNESS | `why is {a} missing so often? / what's going on with ... {a}?` | `why is income missing so often?` | `{'needs_clarification': False, 'goal': 'missingness', 'variables': {'outcome': 'income'}, 'design': 'unknown'}` | design is not applicable to this goal. |
| OUTLIERS | `are there outliers in {a}? / does {a} have any extreme values?` | `are there outliers in income?` | `{'needs_clarification': False, 'goal': 'outliers', 'variables': {'outcome': 'income'}, 'design': 'unknown'}` | design is not applicable to this goal. |
| TRANSFORM | `should {a} be log-transformed? / does {a} need a transformation ...?` | `should income be log-transformed?` | `{'needs_clarification': False, 'goal': 'transform', 'variables': {'outcome': 'income'}, 'design': 'unknown'}` | design is not applicable to this goal. |
